# 0. 표지

안녕하세요, OO조입니다.

저희 팀이 개발한 **“동의대학교 학생 질의응답 RAG 챗봇 시스템”**, dong-gu를 발표하겠습니다.

# 1. 초기목표

학교 생활을 하다 보면 이런 상황, 다들 겪어보셨을 겁니다.

*“수강신청이 언제지? 홈페이지 어디에 있더라…”*

*“중간고사 기간을 모르겠어서 학과 게시판, 학사공지, 대학 홈페이지를 전부 뒤졌는데 다른 내용이 나왔어.”*

동의대학교 공식 홈페이지에는 학사 일정, 장학금, 교직원 연락처, 학과 커리큘럼, 건물 위치 등 방대한 정보가 있지만, 정보가 **수십 개 서브 페이지와 첨부파일**에 분산되어 있어 탐색이 어렵습니다.

또한 기존의 단순 키워드 검색은 질문의 맥락을 이해하지 못해, “기말고사 일정”을 물어보면 관련 없는 공지사항이 먼저 튀어나오는 경우가 많습니다.

그래서 저희는 세 가지 목표를 세웠습니다.

1. **학교 공식 문서를 자동 수집**하는 크롤러 개발
2. **의미 기반 검색**과 **키워드 검색을 결합**한 RAG 파이프라인 구현
3. 학생들이 가장 많이 쓰는 **카카오톡 채널**로 언제든 질문 가능한 챗봇 구축

# 2. 중간발표 진행 요약

중간발표 시점까지 저희가 완료한 사항을 요약하면 다음과 같습니다.

크롤러는 동의대학교 주요 게시판과 정적 안내 페이지를 수집하고, PDF, HWP, 이미지 등 첨부파일까지 텍스트로 변환하는 기능을 구현했습니다.

검색 쪽에서는  BM25 기반 어휘 검색의 기초 파이프라인을 완성했고,

백엔드는 카카오 i 오픈빌더와 연동되는 FastAPI 서버의 기본 골격을 세웠습니다.

중간발표 이후 남은 과제는 **검색 품질 개선**, **도메인 규칙 게이트 적용**, 그리고 **정량 평가 프레임워크 구축**이었습니다.

# 3. 최종 결과

## 3.1 프로젝트 수행 내용

- **시스템 개요**
    
    본 시스템은 세 개의 독립 Docker 컨테이너로 구성됩니다.
    
    **Crawler → RAG Pipeline → Backend → 카카오톡 사용자**
    
    먼저 **Crawler**가 동의대학교 홈페이지를 주기적으로 수집하여 db에 벡터로 저장합니다.
    
    사용자가 카카오톡에서 질문하면 **Backend**(포트 8000)가 웹훅을 수신하고,
    
    내부 API로 **RAG Pipeline**(포트 8001)에 전달합니다.
    
    RAG Pipeline은 Supabase에서 관련 문서를 검색하고 LLM으로 최종 답변을 생성해 반환합니다.
    
    각 컨테이너는 독립적으로 배포·재시작할 수 있어 운영 중 장애 격리가 가능합니다
    
- **시스템 구성 요소 설명**
    - 크롤러
        
        (mermaid 형식 크롤러 다이어그램과 함께 데이트 흐름순으로 설명)
        
    - rag pipeline + backend
- **시스템 설계**
    
    **Fallback 체인 설계**
    
    검색 품질 기준(상위1 점수, 평균점수, 컨텍스트 길이, 중복비율)을 충족하지 못하면 아래 폴백 전략을 순차 시도한다.
    
    ```
    1차 검색 실패
      → vector_only_retry          : 어휘 가중치 제거, 순수 벡터 검색
      → original_query_no_rewrite  : 쿼리 재작성 생략, 원문 그대로
      → relaxed_filters            : 출처·타입 필터 완화
      → increase_top_k             : 후보 집합 확장
      → lexical_only_retry         : BM25 전용
    ```
    
    **하이브리드 점수 융합 방식**
    
    | 모드 | 설명 |
    | --- | --- |
    | `weighted` | 어휘 0.55 + 벡터 0.45 가중합 (기본) |
    | `rrf` | Reciprocal Rank Fusion |
    | `srrf` | Softmax-RRF (실험적, 현재 운영 적용) |
    | `max` | 두 점수 중 최댓값 |
    
    **검색 품질 개선 기법 (최종 적용)**
    
    | 기법 | 구현 위치 | 효과 |
    | --- | --- | --- |
    | 패밀리별 source_type 사전 필터 | `source_policy.py` | 노이즈 문서 검색 단계에서 제거 |
    | dormitory 쿼리 exchange 출처 필터 | `retriever.py` | 국제교류처 공지 혼입 방지 |
    | 교육과정(sub03) URL 섹션 우선순위 | `retriever.py` | 이수표 페이지 raw rank 상승 |
    | 첨부파일 페널티 면제 | `reranker.py` | 첨부파일이 원본인 커리큘럼 문서 보호 |
    | 학과명 개체 boost/penalty | `reranker.py` | 타 학과 문서 억제 |
    | 취업지원센터 source boost | `reranker.py` | 공식 취업지원 페이지 우선 |

## 3.2 데이터베이스 구성

- **document** : 문서의 제목,출처,url 등 문서 자체의 메타데이터만 저장
    
    본문 데이터는 documents_contents에서 관리
    
- **document_contents** : 문서에서 추출된 데이터를 유형별로 저장
    
    `content_type`  속성 도메인 (raw / clean / table / attachment / image / html)으로 이루어지며 저장
    
- **chunks** : rag 검색 단위로 사용되는 텍스트 조각을 저장한다
- **chunk_embeddings** : 각 청크별 임베딩 벡터를 저장

- **query_logs**: 사용자 질문·의도·카테고리 기록
- **response_logs**: LLM 응답과 지연시간(ms) 기록
- **retrieval_logs**: 검색 전략, 점수, 사용된 청크 기록

# 6. 프로그램 설치 메뉴얼

### 사전 요구사항

- Docker Desktop 설치 (Windows/Mac/Linux)
- Docker Compose v2 이상
- Supabase 계정 및 프로젝트 생성
- OpenAI API 키 (또는 Ollama 로컬 설치)

### 설치 절차

**1. 저장소 클론**

```bash
git clone https://github.com/woogissi/dong-gu/branches
cd dong-gu
```

**2. 환경 변수 설정**

```bash
cp .env.example .env
```

`.env` 파일을 편집하여 아래 항목 입력:

```
# OpenAI
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini

# 임베딩 모델 (자동 다운로드)
EMBEDDING_MODEL=nlpai-lab/KoE5

# 하이브리드 검색 설정 (운영 권장)
HYBRID_SCORE_MODE=srrf
HYBRID_SRRF_BETA=20
HYBRID_LEXICAL_WEIGHT=0.55
HYBRID_VECTOR_WEIGHT=0.45

# 벡터 전용 검색 패밀리 (검색 품질 최적화)
RAG_VECTOR_ONLY_FAMILIES=department_curriculum,building_location,welfare_facility,campus_address,person_title,course_registration,academic_schedule,seasonal_course_registration,specific_scholarship,graduation,certificate,scholarship,grade,career
```

**3. DB 초기화**

SQL Editor에서 아래 명령 실행:

```sql
-- pgvector 확장 활성화
create extension if not exists vector;

-- 문서 청크 테이블
create table document_chunks (
  id bigserial primary key,
  content text,
  embedding vector(768),
  source_url text,
  doc_type text,
  created_at timestamptz default now()
);

-- 벡터 인덱스
create index on document_chunks
  using ivfflat (embedding vector_cosine_ops)
  with (lists = 100);
```

**4. Docker 서비스 시작**

```bash
# 전체 서비스 실행
docker compose up -d

# 서비스별 실행
docker compose up rag -d      # RAG (port 8001)
docker compose up backend -d  # Backend (port 8000)
```

**5. 초기 문서 수집 (크롤러 실행)**

```bash
# 전체 크롤링 (최초 실행)
docker compose run --rm crawler \
  python -m crawler.run.run_crawl_to_rag --fail-on-partial

# 증분 업데이트 (이후 주기적 실행)
docker compose run --rm crawler \
  python -m crawler.run.run_crawl_to_rag --since-date 2026-05-01
```

**6. 동작 확인**

```bash
# RAG 헬스체크
curl http://localhost:8001/health

# Backend 헬스체크
curl http://localhost:8000/health

# 쿼리 테스트
curl -X POST http://localhost:8001/query \
  -H "Content-Type: application/json" \
  -d '{"query": "수강신청 기간이 언제야?"}'
```

**7. 검색 품질 평가 실행**

```bash
# 36개 대표 질문 자동 평가
docker compose run --rm rag \
  python -m rag.evaluation.retrieval.evaluate_retrieval \
  --dataset datasets/real_queries.yaml --tag eval_run_1
```

**8. 카카오 i 오픈빌더 연동**

1. 카카오 i 오픈빌더에서 챗봇 생성
2. 스킬(Skill) 설정 → 스킬 서버 URL: `https://[배포도메인]/api/chat`
3. 시나리오 → 폴백 블록 → 스킬 연결
